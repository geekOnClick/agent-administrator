# ReAct-цикл валидации счетов (bills)

Режим `bills` реализует агентский цикл проверки коммунальных счетов:

1. Агент скачивает документы с Яндекс.Диска в папку `docs` (тот же YandexDiskService, с retry-логикой при сетевых ошибках).
2. Документы (PDF, DOC/DOCX, XLS/XLSX, ODT) передаются в RouterAI (модель из `AIROUTER_MODEL`) для валидации.
3. Модель анализирует каждый документ и возвращает JSON с покрытыми/недостающими категориями.

### Поддерживаемые категории

| Ключ | Описание |
|---|---|
| `electricity` | оплата за электричество |
| `heat` | оплата за теплоэнергию |
| `water` | оплата за водоснабжение и содержание/работу сточных вод |
| `garbage` | оплата за вывоз мусора |
| `maintenance` | оплата за содержание помещения |

### Правила валидации

- Валидными документами считаются **счета на оплату И счета-фактуры** (УПД, УКД).
- Каждый документ должен содержать сумму к оплате.
- Все 5 категорий должны быть покрыты для успешного завершения цикла.
- При отсутствии категорий или ошибке модель перечисляет недостающие категории в терминале.
- Пользователь добавляет недостающие документы на Яндекс.Диск и вводит `retry`.
- При исчерпании токенов RouterAI цикл приостанавливается с сообщением об этом — пополните баланс и введите `retry`.
- При успешной валидации всех 5 категорий счета автоматически раскладываются по папкам месяца (`organize_bills`), затем в файл-таблицу учёта "Администрирование_2_0.docx" дозаписывается новая строка с суммами текущего месяца по каждой категории (теплоэнергия, электроэнергия, содержание помещения, водоканал, вывоз мусора).
- Сразу после дозаполнения таблицы агент переиндексирует векторную базу данных FalkorDB (BillsLedgerVectorService, узел `:BillRow`) на основе актуального содержимого docx-таблицы (все строки, эмбеддинги через Ollama nomic-embed-text). После этого цикл ПРИОСТАНАВЛИВАЕТСЯ и предлагает оплатить счета.
- Перед предложением оплаты в блоке "Детализация" выводится конкретная сумма каждого счёта (а не признак её наличия) и итоговая сумма к оплате по всем счетам.

## Векторный поиск по таблице учёта (режим ask)

- Знания из таблицы учёта хранятся в векторной базе FalkorDB (граф, узел `:BillRow`).
- Агент удалил режим `talk` и ввёл режим `ask`: пользователь задаёт вопрос командой `ask <вопрос>`, агент выполняет векторный поиск по FalkorDB и возвращает ответ модели только на основе найденных строк таблицы.
- Для работы `ask` необходимо, чтобы векторная база была актуализирована хотя бы один раз (автоматически происходит в цикле `bills`).

## Отчёт по периоду (режим report)

- Команда `report MM/YY-MM/YY` (например `report 05/26-08/26`) строит отдельный .docx-отчёт с суммами по услугам за указанный диапазон месяцев (включительно), в том же формате таблицы, что и "Администрирование_2_0.docx".
- Источник данных — актуальная таблица учёта (файл только читается, не изменяется).
- Отчёт сохраняется в `/home/geekonclick/Рабочий стол/Администрирование2026` (папка настраивается через `BILLS_REPORT_OUTPUT_DIR`).

## Пауза на оплату и проверка квитанций (continue)

После раскладывания счетов по папкам цикл ждёт, пока пользователь оплатит счета и положит квитанции (чеки по операции) в те же папки, где лежат счета.

1. Пользователь оплачивает счета и сохраняет квитанции/чеки в соответствующие папки.
2. Пользователь вводит команду `continue` в терминале.
3. Модель вызывает tool `check_bill_receipts`, который для каждой папки со счетами проверяет только факт наличия квитанции об оплате (без сравнения сумм).
4. Для каждого файла в папке (кроме самих счётов) классификация всегда выполняется в режиме **HARD** через RouterAI (без обращения к локальной модели — так распознавание документов быстрее и точнее). Роутер EASY/HARD остаётся только для раскладывания счётов в `organize_bills`. Используемая модель всегда логируется в консоль видом пользователю. Файлы, признанные не квитанциями, игнорируются и не считаются ошибкой.
5. Если во всех папках найдена хотя бы одна квитанция — цикл завершается.
6. Если хотя бы в одной папке квитанция не найдена — цикл снова ПРИОСТАНАВЛИВАЕТСЯ, ошибка выводится в терминал, и снова ожидается `continue` после исправления.
7. Если во всех папках квитанции найдены, агент дополнительно вызывает tool `generate_sordisu_bill`:
   - создаёт папку текущего месяца (на русском, с маленькой буквы) в `/home/geekonclick/Рабочий стол/Администрирование2026/Сордису по месяцам`;
   - копирует туда все файлы из папки-шаблона `шаблон_для_агента`;
   - в файле `счет.doc` подставляет реальную дату счёта (текущее число, месяц в родительном падеже, год) вместо `«текущее число» «текущий месяц» «текущий год»` и месяц аренды (следующий месяц после текущего) вместо `«следующий месяц после текущего»`; остальной текст документа не меняется; сохраняет результат как pdf и удаляет исходный `счет.doc`;
   - в файле `справка-расчет.docx` подставляет дату справки (аналогично `счет.doc`) в строке `Справка-расчет от ...`, а в наименованиях строк таблицы — месяц, предшествующий текущему (`... за <месяц> <год> г.`);
   - для каждой строки таблицы (электроэнергия, теплоэнергия, вывоз мусора, водоснабжение) находит файлы соответствующих счетов текущего месяца (по манифесту `organize_bills`) и отправляет каждый из них на анализ модели **HARD**-уровня через RouterAI (`extractBillColumns`), которая извлекает единицу измерения, количество, цену за единицу, сумму, НДС%, сумму НДС и итог с НДС; агент только агрегирует полученные от модели значения (суммирует при нескольких счетах на категорию) и подставляет их в столбцы таблицы — самостоятельного парсинга/сопоставления счетов агент не выполняет;
   - пересчитывает итоговую сумму по таблице и её расшифровку словами на русском, сохраняет результат как pdf и удаляет исходный `справка-расчет.docx`;
   - в файле `счет коммуналка.docx` подставляет дату счёта (аналогично `счет.doc`), месяц оказания услуг (предшествующий текущему) в строке `Оплата коммунальных услуг за ... 2026 г (...)`, а итоговую сумму и её расшифровку словами берёт готовыми из уже рассчитанной справки-расчёта (повторно не пересчитывает); сохраняет результат как pdf и удаляет исходный `счет коммуналка.docx`;
    - рекурсивно обходит папку `Документы по месяцам/<текущий месяц>` (созданную ранее на шаге скачивания) и копирует все найденные файлы счетов и квитанций плоско, без подпапок, прямо в папку месяца `Сордису по месяцам/<текущий месяц>` (при совпадении имён файлов из разных категорий добавляется суффикс `(1)`, `(2)` и т.д.; служебные манифесты `_expected_amount.json` и lock-файлы не копируются).
8. После этого в терминал выводится сообщение о завершении агентского цикла, и выполнение CLI-скрипта завершается (процесс закрывается).
